# Contributing

Use PHP 8.2+, separate source/build output and immutable native financial identifiers. Keep signing, webhook cryptography, integer money and settlement evidence in the shared Lunixi PHP SDK; this repository is the WHMCS lifecycle adapter. No direct card collection, arbitrary gateway URLs, browser-paid transitions or fresh keys on unknown results.

Run the README build, artifact, PHPCS, PHPStan level 8, dependency audit and disposable MariaDB contract checks. Use the official licensed acceptance matrix for changes affecting WHMCS helpers, hooks, models, permissions or invoice semantics. Never call contract stand-ins a successful native install. Do not redistribute encoded WHMCS source or license material.

All user-facing strings require matching English/Turkish dictionary keys and native addon language files. Preserve RTL-compatible layouts and original brand assets. No secrets/PII in logs, fixtures, screenshots, issues or exported ZIPs. Add meaningful rollback/idempotency/security regression coverage for changes. Prefer minimal diffs and include validation plus material limits in review descriptions.

The runtime ZIP bundles PHP-Scoper output and a standalone loader. Merchants must not need Composer or a sibling checkout. Build tools and tests stay out of the merchant ZIP. Test-only DB names are constrained to `lunixi_whmcs`; connection files stay outside the repository.
